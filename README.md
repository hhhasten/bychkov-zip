# bychkov-zip

`byz` — консольний архіватор: складає файли й папки в один зашифрований файл
`.byz` і повертає їх назад.

Репозиторій: <https://github.com/hhhasten/bychkov-zip>

**Статус: MVP (v0.1.0).** Ядро працює й покрите тестами. Формат `.byz` версії 1
заморожений: він читається й пишеться поточним кодом, але ще не містить LZ77,
багатотомності, CRC32 та класифікатора. Це напрямки подальшого розвитку, а не
заявлена сумісність із SARC.

## Можливості

- `create` — файли й папки (рекурсивно) в один архів;
- `extract` — розпакування з перевіркою шляхів і захистом від overwrite;
- шифрування AES-256-GCM, ключ із пароля через Argon2id;
- стиснення Гаффмана з автоматичним fallback у `STORED`, якщо стиснення не дає виграшу;
- протокол прогресу в `stdout` для GUI та скриптів;
- зрозумілі коди виходу й машиночитні помилки.

## Вимоги

- Rust **1.85+** (видання 2024).

## Збірка

```sh
cd core
cargo build --release
```

Готовий бінарник:

- Linux / macOS: `core/target/release/byz`
- Windows: `core/target/release/byz.exe`

Під час розробки можна запускати без збірки:

```sh
cd core
cargo run --release -- --help
```

## Використання

```text
byz create  <archive.byz> <input>... [--force]
byz extract <archive.byz> [-o <dir>]
```

Аліаси: `c` для `create`, `x` для `extract`.

### Приклади

Заархівувати папку `docs` і файл `notes.txt`:

```sh
byz create backup.byz docs notes.txt
```

Заархівувати поточну папку (вона потрапить в архів під своїм ім'ям):

```sh
byz create backup.byz .
```

Перезаписати наявний архів:

```sh
byz create backup.byz docs --force
```

Розпакувати в `restored/` (папка створюється автоматично):

```sh
byz extract backup.byz -o restored
```

Розпакувати в поточну папку:

```sh
byz extract backup.byz
```

## Пароль

- У терміналі пароль вводиться приховано. `create` просить його двічі й
  перевіряє збіг, `extract` — один раз.
- Якщо `stdin` не є терміналом (pipe, CI, скрипт), читається **один рядок**.
  Завершальні `\r` / `\n` відрізаються, пробіли всередині й на краях
  зберігаються.
- Порожній пароль і відсутність рядка — помилка `BAD_ARGS`.
- Пароль у пам'яті обгорнутий у `zeroize` і затирається після використання.

Приклад для скрипта:

```sh
printf '%s\n' "$PASSWORD" | byz create backup.byz docs
```

## Протокол stdout / stderr

`stdout` призначений для машинного читання. Під час `create` / `extract` туди
йдуть лише рядки двох видів:

```text
byz-status:<stage>
byz-progress:<0..100>
```

Стадії: `analyzing`, `compressing`, `encrypting`, `decrypting`, `extracting`,
`complete`. Прогрес монотонний і закінчується `100`.

Увесь людський текст, підказки й помилки йдуть у `stderr`. Помилка має вигляд:

```text
byz-error:<CODE>:<message>
```

Наприклад:

```text
byz-error:AUTH_FAILED:wrong password or corrupted archive
```

## Коди виходу

| Код | `CODE`        | Значення                                      |
|----:|---------------|-----------------------------------------------|
| 0   | —             | успіх                                         |
| 1   | `INTERNAL`    | внутрішня помилка                             |
| 2   | `BAD_ARGS`    | неправильні аргументи, порожній пароль тощо   |
| 3   | `AUTH_FAILED` | неправильний пароль або пошкоджений архів     |
| 4   | `IO`          | помилка файлової системи                      |
| 5   | `UNSAFE_PATH` | небезпечний шлях в архіві                     |
| 6   | `TOO_LARGE`   | перевищено ліміт розміру                      |
| 7   | `BAD_FORMAT`  | файл не є `.byz` або формат пошкоджений       |

Коди задані в `core/src/error.rs`.

## Обмеження

Це свідомі обмеження MVP, а не недогляд:

- **Один том.** Максимальний розмір вхідних даних — 500 МіБ, архіву — 500 МіБ + 16 МіБ.
- **Усе в пам'яті.** Архів читається й пишеться цілком; під час роботи потрібно
  орієнтовно 2–3 розміри архіву оперативної пам'яті.
- **Лише Гаффман.** LZ77 ще не реалізований, тому тексти й логи стискаються
  помірно (приклад: 900 КБ повторюваного тексту → ~503 КБ). Дані з високою
  ентропією зберігаються як є.
- **Порожні папки не зберігаються.** Архів містить лише файли; порожня папка
  після розпакування не з'явиться.
- **Символьні посилання.** Всередині папок вони пропускаються; якщо передати
  symlink безпосередньо — `BAD_ARGS`.
- **Метадані не зберігаються.** Час зміни, права доступу, власник і атрибути
  після розпакування не відновлюються.
- **Немає перезапису під час розпакування.** Якщо хоч один цільовий файл уже
  існує, `extract` завершується з `IO` і не пише нічого.
- **Правила імен.** Заборонені абсолютні шляхи, `..`, порожні компоненти,
  керуючі символи, `\` і `:` у компонентах, імена, що закінчуються крапкою або
  пробілом, та зарезервовані імена Windows (`CON`, `NUL`, `COM1`, …).
- **Формат v1.** Будь-яка зміна розкладки байтів вимагає нової версії формату.

Деталі формату: [`docs/FORMAT.md`](docs/FORMAT.md).

## Структура проєкту

```text
core/                   Rust-ядро і CLI
├── src/
│   ├── main.rs         точка входу CLI
│   ├── lib.rs          публічні модулі ядра
│   ├── cli/            розбір аргументів, пароль, протокол, команди
│   ├── archiver/       створення й розпакування архівів
│   ├── format.rs       заголовок і метадані .byz
│   ├── crypto.rs       Argon2id + AES-256-GCM
│   ├── huffman/        стиснення Гаффмана
│   ├── entropy.rs      оцінка стисливості
│   ├── input.rs        збір файлів і папок
│   ├── path.rs         перевірка шляхів
│   └── error.rs        `ByzError` і коди виходу
├── tests/cli.rs        наскрізні тести CLI
└── Cargo.toml
gui/                    GUI (відкладено)
docs/FORMAT.md          опис формату .byz
AGENTS.md               правила для ИИ-агентів, які виконують завдання
TASKS.md                завдання для команди
```
